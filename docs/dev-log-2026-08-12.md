# EasyTierBar 开发日志 — v2 重构

**日期**: 2026-08-12
**主题**: 从「多 launchd 单元 + 每次弹密码」转为「常驻守护进程 + Web-Managed 模式 + 日常免密」

---

## 背景：v1 的根本问题

v1（`dev-log-2026-04-20.md` 记录）把 app 建模成「管理多个 launchd 单元，每个单元 = 一条 `-w <url>` 命令」，并在菜单栏切换。这有两个层面的问题：

1. **体验**：每次 start/stop 都 `launchctl load/unload`，每次弹管理员密码。
2. **范式错配（更根本）**：作者实际用的是 EasyTier **Web-Managed（config-server）模式**——`-w udp://web-et.seeyon.ink:22020/admin` 连的是一个 `easytier-web` 配置中心，网络拓扑在 Web 端统一配置、由配置中心 `reconcile` 下发到本地。在这种模式下：
   - 本地只需要**一个常驻 core 进程**，`-w` 只是「连哪个配置中心」这一个连接信息；
   - 网络实例的配置不该由本地 app 持有/切换；
   - v1 的「多个 -w 配置本地切换」本质是把 Web-Managed 模式当成了 Multi-instance Standalone 模式。

经确认用户「一个配置中心就够、不需要多网络切换」，决定按 Web-Managed 范式整体重构。

## 架构转变

| | v1 | v2 |
|---|---|---|
| 服务模型 | N 个 launchd 单元，每个 = 一条 `-w` 命令 | 1 个常驻 LaunchDaemon：`--daemon --config-dir -w <中心>` |
| 切换网络 | 卸载重装 launchd（弹密码） | 不切换——网络实例由 Web 中心下发 |
| 日常密码 | 每次 start/stop 都弹 | 仅安装/卸载守护进程弹一次 |
| 状态检测 | `pgrep`（只知进程在不在） | RPC `easytier-cli node info`（进程+RPC 双重可达） |
| 配置模型 | `[NetworkConfig]` 数组 + 选中项 | 单条：配置中心地址 + Web 控制台地址（两字段独立） |
| 网络启停 | 本地菜单 | Web 控制台（config-server `reconcile` 范式） |

## 定位取舍：纯看护者

本地 app **不提供「启动/停止网络」按钮**。理由：config-server 模式下，本地停掉的网络实例会被 Web 端 `reconcile_managed_network_configs` 重新拉起，本地「停止」语义不干净。daemon 一旦安装即开机自启、KeepAlive 自愈、常驻在线；想临时断开去 Web 控制台停实例，或卸载守护进程。

## 本次完成的工作

### 1. `ConfigManager.swift` — 重写为单条配置

`[NetworkConfig]` 数组模型整体删除，改为：

```swift
struct CenterConfig: Codable, Equatable {
    var configServerUrl: String   // -w 的值，core 连配置中心用
    var webConsoleUrl: String     // 浏览器打开的 web 控制台地址
}
```

两字段独立、各自必填——经确认二者协议/端口/路径都不同（如 `udp://host:22020/admin` vs `https://host`），不能互相推导。存单条到 `UserDefaults["centerConfig"]`。

### 2. `ServiceManager.swift` — 服务模型重构

- **新增** `isDaemonInstalled()`：检测 plist 存在（`FileManager`，免密）
- **新增** `installDaemon()`：AppleScript sudo 一次性完成 `pkill` → `mkdir configDir` → `unload` 旧的 → `cp` 新 plist → `load`。pkill 用于清理任何手动运行的 core，避免 15888 端口占用导致新 daemon 起不来
- **新增** `uninstallDaemon(removeConfigs:)`：`unload` → `rm plist` → `pkill`，可选清除 config-dir
- **改造** `checkStatus()`：返回 `DaemonStatus` 枚举（`notInstalled` / `installedNotReachable` / `running`）
- **改造** `generatePlist()`：`ProgramArguments` 改为 `--daemon --config-dir <dir> -w <url> --rpc-portal 127.0.0.1:15888`
- **新增** `coreReachableSync()`：跑 `easytier-cli node info`，退出码 0 = RPC 可达（替代 pgrep）
- **删除** v1 的 `startService` / `stopService` / `isProcessRunning`（pgrep）
- **保留** `fetchPeerList`（已可用）、`runAppleScriptSudo`（install/uninstall 仍用）

### 3. `AppDelegate.swift` — UI 重做

- 三态状态：运行中(绿) / 守护进程未响应(黄) / 未安装(灰)，用 `contentTintColor` 上色
- 菜单：状态行 + 已连接节点 ▸ + 打开 Web 控制台 + 安装/卸载守护进程 + 配置中心设置 + 关于 + 退出
- `openWebConsole`：`NSWorkspace.shared.open(center.webConsoleUrl)`
- `runCenterDialog`：两字段对话框（配置中心地址 + Web 控制台地址），首启必填
- `editCenterConfig`：改地址后若 daemon 已装，提示「需重装才生效」并触发重装
- 删除 v1 的多配置菜单、`toggleService`、`setToggleState`
- `quit` 不再停服务（daemon 常驻，退出 app 不影响网络）

### 4. 清理

- 删除工作区死文件 `easytier-web`（19M）、`easytier-web-embed`（22M）——gitignored、无任何引用
- 重写 `scripts/generate_icon.py`：移除被 `final` 覆盖的废弃绘制段（原 28-56 行在 `img` 上画的内容从未被保存），删死函数 `rounded_rect` / `gradient_bg` 及未用的 `import math`

## 关键技术决策

| 决策 | 选择 | 原因 |
|------|------|------|
| 守护进程模式 | `--daemon --config-dir` | 单进程常驻，网络实例由 Web 中心下发持久化，本地无需多单元 |
| 不做本地网络启停 | 网络管理全在 Web | config-server `reconcile` 会拉起本地停的实例，本地「停」语义不干净 |
| 状态检测 | RPC `node info` | 比 pgrep 准（进程在 + RPC 通双重判定） |
| 配置模型 | 单条两字段 | 用户只用一个 Web 中心；两地址独立不能推导 |
| 日常免密 | RPC 走 `127.0.0.1:15888` | 非 root 可访问（v1 的 peer list 已验证） |
| 安装前 pkill | 先杀任何手动 core | 防止端口占用导致新 daemon 启动失败 |

## 已知限制 / 后续

1. 仅支持 macOS aarch64（Apple Silicon）
2. 配置中心地址变更需重装守护进程（弹一次密码）——低频操作，可接受
3. `easytier-cli peer list` 字段可能随核心版本变化（代码用宽松的 `String?` 容错）
4. 未内嵌 WebView（保持「系统浏览器打开」轻量做法；日后若想内嵌可评估 SwiftUI 窗口 + WKWebView）
