# EasyTierBar 开发日志 — 启动 / 停止能力

**日期**: 2026-08-14
**主题**: 补上「启动 / 停止」菜单项；sudoers 免密方案尝试后废弃

---

## 背景

v2 的「纯看护者」定位（见 `dev-log-2026-08-12.md`）最初有意没做本地启停，理由是
config-server 模式下本地停掉的实例会被配置中心 `reconcile` 重新拉起。实际使用中这个取舍
不成立：用户需要临时停掉 VPN，而唯一手段「卸载守护进程」要弹密码、删配置，太重。

## 语义修正

「停止」的正确对象不是**某个网络实例**（那才会被 reconcile 拉起），而是**整个 core 守护进程**：

- **停止** = `launchctl unload` 整个 LaunchDaemon：TUN 拆除、配置中心连接一起断开，
  没有东西会被 reconcile 拉起。**临时性**：plist 仍在，重启电脑后 launchd 自动加载恢复。
- **启动** = `launchctl load -w`：恢复运行。
- **永久移除** = 「卸载守护进程」。

## 方案演变：sudoers 免密 → 直接弹密码

第一版实现走了 sudoers 免密路线（安装时写入 `/etc/sudoers.d/easytierbar`，允许免密执行
对本 plist 的 `launchctl load/unload`，`visudo -cf` 校验后安装），启停不弹密码。

**用户反馈否决了这个方案**：不需要为省密码引入系统级 sudoers 修改，需要输密码就输。
遂全部移除：

- `installDaemon` 不再写 sudoers
- `uninstallDaemon` 保留对 `/etc/sudoers.d/easytierbar` 的幂等清理（清掉历史遗留）
- `startVPN/stopVPN` 改为和其他操作一致的 AppleScript sudo（弹管理员密码框）
- 菜单文案从「启动/停止 VPN」简化为「启动」「停止」

教训：为省一步用户并不介意的操作（输密码）而引入额外的系统修改（sudoers 文件），
是本末倒置的过度设计；系统痕迹越少越好。

## 状态机：第五态 `stopped`

```
notInstalled          plist 不存在            → 灰「未安装」
stopped               plist 在 + 进程不在      → 灰「已停止（重启电脑后自动恢复）」
installedNotReachable 进程在 + RPC 不通       → 黄「未响应」
noNetwork             RPC 通 + 无对端 peer    → 橙「未连通网络」
running               RPC 通 + 有 peer        → 绿「运行中」
```

UI：菜单第一项为动态「启动 / 停止」（未安装时隐藏）；peer 面板在停止时显示「(已停止)」。
