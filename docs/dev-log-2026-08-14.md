# EasyTierBar 开发日志 — 一键启停 VPN（sudoers 免密方案）

**日期**: 2026-08-14
**主题**: 补上「启动 / 停止 VPN」能力，日常启停免密、秒级完成

---

## 背景

v2 的「纯看护者」定位（见 `dev-log-2026-08-12.md`）有意没做本地网络启停，理由是
config-server 模式下本地停掉的实例会被配置中心 `reconcile` 重新拉起，本地「停止」语义不干净。
实际使用中这个取舍不成立：用户需要临时停掉 VPN（比如不想现在走公司网络），
而唯一手段「卸载守护进程」要弹密码、删配置，太重。

## 语义修正

之前对「停止」的理解错了。正确的停止对象不是**某个网络实例**（那才会被 reconcile 拉起），
而是**整个 core 守护进程**：

- **停止 VPN** = `launchctl unload` 整个 LaunchDaemon：TUN 拆除、配置中心连接断开。
  没有东西会被 reconcile 拉起（core 都没了）。**临时性**：plist 仍在
  `/Library/LaunchDaemons/`，重启电脑后 launchd 自动加载恢复。
- **启动 VPN** = `launchctl load -w`：恢复运行。
- **永久移除** = 「卸载守护进程」（删 plist + sudoers + 可选清配置）。

## 免密方案：最小 sudoers 规则

`launchctl load/unload`（system domain）需要 root，若直接做会退回 v1「每次启停弹密码」。
采用商业 VPN 客户端通行做法——**安装时写入一条最小授权的 sudoers 规则**：

```
/etc/sudoers.d/easytierbar   # 0440
<user> ALL=(root) NOPASSWD: \
    /bin/launchctl unload /Library/LaunchDaemons/com.easytier.core.plist, \
    /bin/launchctl load   /Library/LaunchDaemons/com.easytier.core.plist, \
    /bin/launchctl load -w /Library/LaunchDaemons/com.easytier.core.plist
```

安全性考量：
- **最小授权**：只允许对**本 app 的 plist** 做 load/unload 三种精确命令组合。
  不能改 plist 内容（需 root 写）、不能启停其他服务、不能执行任意 launchctl。
- 写入前先落临时文件并 `/usr/sbin/visudo -cf` 校验语法，校验通过才安装，
  杜绝写坏 sudoers 导致系统 sudo 失效。
- 卸载守护进程时同步删除该文件。

app 侧 `startVPN/stopVPN` 用 `sudo -n`（non-interactive）执行——免密规则生效时秒回；
未生效（旧安装）则明确提示「请先重新安装守护进程一次」。

## 状态机扩展：第五态 `stopped`

```
notInstalled          plist 不存在            → 灰「未安装」
stopped               plist 在 + 进程不在      → 灰「已停止（重启电脑后自动恢复）」
installedNotReachable 进程在 + RPC 不通       → 黄「未响应」
noNetwork             RPC 通 + 无对端 peer    → 橙「未连通网络」
running               RPC 通 + 有 peer        → 绿「运行中」
```

UI：菜单第一项变为动态的「启动 VPN / 停止 VPN」（未安装时隐藏）；
peer 面板在 stopped 时显示「(VPN 已停止)」。

## 兼容与迁移

存量安装（无 sudoers）在点启停时会得到明确指引：重新安装一次守护进程（弹一次密码）
即写入免密规则，此后启停免密。
